# Архітектура AI-агента

## Проблеми, які вирішує агент

Агент автоматизує рутинні процеси створення проєкту: генерацію шаблонного коду, налаштування інструментів збірки та тестування, а також конфігурацію CI/CD пайплайнів, усуваючи необхідність ручного написання boilerplate-коду.

## Використовувані Skills

1. `project-scaffold` — створення базової структури TypeScript проєкту, ініціалізація `package.json` та `tsconfig.json`.
2. `build-and-test` — додавання скриптів збірки, встановлення Vitest та написання базового юніт-тесту.
3. `github-actions` — генерація `.github/workflows/ci.yml` для автоматичного тестування на трьох ОС.

## Доступні Commands

- `git-init` — ініціалізація Git та `.gitignore`.
- `create-project` — запуск project-scaffold.
- `create-build` — запуск build-and-test.
- `create-actions` — запуск github-actions.
- `check` — верифікація згенерованих файлів та тестів.
- `init` (Оркестратор) — послідовний виклик усіх команд.

## Передача даних між етапами

Етапи працюють послідовно в єдиному робочому просторі. Результат роботи кожної команди (створені файли та конфігурації) стає вхідними даними для наступної. Наприклад, `create-build` покладається на наявність `package.json`, створеного на етапі `create-project`.

## Обробка помилок оркестратором

Оркестратор перевіряє код повернення (exit code) після кожного етапу. Якщо будь-який етап (наприклад, локальне тестування під час `check`) завершується з помилкою, процес негайно зупиняється з виведенням повідомлення, щоб запобігти коміту неробочого коду.
